## Что решаем

Каждый гайд советует опубликовать `llms.txt`. Ни один не показывает строку лога, где этот файл кто-то запросил.

Я прочитал свой. Одна машина, несколько маленьких сайтов, access-логи nginx по сайтам, с 19 июля по 12 августа 2026.

В окне дыра. Ничего между 20 и 28 июля ротацию не пережило, так что дальше — 16 дней записей.

Это трафик одного оператора, а не выборка по вебу. Но это замер, а у советов вокруг нет и его.

Первым замер нашёл меня. Мой собственный адрес сделал за окно 4 221 запрос к этой машине, 81 из них — под именем краулера.

## Шаги

Сначала прочитать весь период целиком, и только потом — отдельного агента. Мой собственный адрес — второй столбец.

| Агент | В логе | Мои | Остальное |
|---|---|---|---|
| ChatGPT-User | 341 | 4 | 337 |
| YandexBot | 244 | 3 | 241 |
| bingbot | 155 | 3 | 152 |
| OAI-SearchBot | 82 | 4 | 78 |
| Googlebot | 79 | 4 | 75 |
| GPTBot | 55 | 14 | 41 |
| meta-externalagent | 41 | 3 | 38 |
| Claude-User | 34 | 12 | 22 |
| PerplexityBot | 25 | 7 | 18 |
| Amazonbot | 22 | 2 | 20 |
| Applebot | 7 | 3 | 4 |
| ClaudeBot | 6 | 6 | 0 |
| Perplexity-User | 3 | 3 | 0 |

Две строки мои целиком. ClaudeBot и Perplexity-User обнуляются, как только мой адрес выходит из подсчёта.

Прошлая версия страницы валила эти строки на неизвестный сканер. Там было написано, что один клиент прислал с единственного адреса 56 разных имён краулеров.

Счёт был почти верный, а клиент — я. С этого адреса за окно пришло 56 разных строк `User-Agent`, 18 из них — имена краулеров. Все из `curl`, которым я проверял собственные правила доступа.

`Google-Extended` был в этом наборе, и своего user agent у него нет. Это управляющий токен для `robots.txt`, а ходят обычные агенты Google.

То есть строка была настоящая, а краулер — нет. `Google-Extended` вы не выгрепаете из своего лога никогда, если только не наберёте его сами себе.

### Самая большая строка — та, которую я не могу никому приписать

`ChatGPT-User` стоит первым, и именно эту строку лог объясняет хуже всего. Агент срабатывает, когда человек вставляет ссылку в чат.

Четыре запроса из 341 пришли с моего адреса, из `curl` с руками выставленной строкой. Остальные 337 — с 272 адресов, которые я ни с какими опубликованными диапазонами не сверял.

Если агент настоящий, запрос уходит с серверов OpenAI и когда ссылку вставил я, и когда посторонний. По адресу нас в любом случае не различить.

Сказать по логу можно немного. Эти 337 запросов покрывают все часы суток и 15 из 16 дат окна. 38 из них попадают в пять минут от запроса с моего адреса.

Одиннадцать процентов — слабый довод против «это всё я» и вообще не довод о том, кто это был. Чтобы развести две версии, нужно окно, в которое я сайт не трогаю, а такого окна я не снимал.

Всю строку `ChatGPT-User` надо читать так. Это счёт обращений агента, которого обязан запустить человек, и человек не назван.

### Что забирали

AI-агенты — ChatGPT-User, OAI-SearchBot, GPTBot, PerplexityBot, Perplexity-User, Claude-User, ClaudeBot и meta-externalagent вместе, с вычтенным моим адресом:

| Путь | Запросов |
|---|---|
| `/` | 280 |
| Пост со сравнением моделей speech-to-text | 64 |
| `/robots.txt` | 56 |
| Пост о расшифровке голосового в Telegram | 18 |
| `/ru` | 17 |
| `/sitemap.xml` | 14 |
| Тот же пост со сравнением, по-русски | 6 |
| Тот же пост о расшифровке, по-русски | 2 |
| `/llms.txt` | 0 |

### Сорок пять обращений к llms.txt, сорок четыре из них мои

`llms.txt` за весь период запросили 45 раз, всеми клиентами вместе. 44 запроса пришли с моего адреса.

Единственный чужой — `SiteAuditBot` от Semrush, 11 августа, ответ 200. Ни один AI-агент файл не просил вообще.

Прошлая версия страницы писала «примерно по одному запросу на агента» и называла файл оглавлением, в которое заглядывают. Это чтение было одним моим циклом.

Семнадцать таких строк укладываются между 18:21:12 и 18:21:15 седьмого августа, по одной на имя краулера, все с моего адреса. Это `curl`, идущий по списку user agent, а не тринадцать вендоров, пришедших за четыре секунды.

Так что `llms.txt` — не маршрут, по которому ходят агенты. На этой машине в это окно он не был даже оглавлением. Вывод сохранил направление и потерял цифру.

### Порядок работы

1. **Писать лог по сайту, а не по машине** — строка `access_log` внутри каждого блока `server`.

   ```nginx
   server {
       server_name example.com;
       access_log /var/log/nginx/example.access.log;
   }
   ```

   Один общий лог без `$host` в `log_format` не скажет, на какой сайт пришёл запрос.
2. **Открывать ротированные архивы, а не только сегодняшний файл** — `zcat -f` читает и обычные, и gzip.

   ```bash
   zcat -f /var/log/nginx/example.access.log* | wc -l
   ```

   Глубину хранения смотреть в конфиге `logrotate`. Это и есть ваше настоящее окно.
3. **Узнать свой адрес раньше, чем считать что-либо** — одна команда, и она меняет все таблицы ниже.

   ```bash
   curl -s https://api.ipify.org
   ```

   Мой лежал в логе 4 221 раз под 56 разными user agent. Две недели я читал это как трафик.
4. **Вычитать адрес, а не только свой `curl`** — браузер, smoke-тест и подделанный агент падают в тот же файл.

   ```bash
   zcat -f /var/log/nginx/example.access.log* | awk '$1 != "203.0.113.9"'
   ```

   Фильтр по `curl` поймал 26 из 44 моих строк с `llms.txt`. Остальные 18 — мои же имена краулеров и мой браузер.
5. **Посчитать агентов за всё окно** — по одному совпадению на запрос, без учёта регистра.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | awk 'match(tolower($0), /chatgpt-user|oai-searchbot|gptbot|perplexitybot|perplexity-user|claude-user|claudebot|meta-externalagent|googlebot|bingbot|yandexbot|applebot|amazonbot/) {
         print substr(tolower($0), RSTART, RLENGTH)
       }' \
     | sort | uniq -c | sort -rn
   ```

   Очевидный вариант через `grep -oE` неверен дважды, и эта страница его публиковала. Bing зовёт себя строчными `bingbot`, так что регистрозависимый шаблон не находит его вовсе.
   Чините регистр — вылезает вторая ошибка: `grep -o` печатает вхождения, а не строки. Запрос от bingbot называет себя дважды: в токене и в URL `+http://…/bingbot.htm`.
   В этом окне это 336 вхождений против 155 запросов. `awk` берёт первое совпадение в строке: одна строка — один запрос.
6. **Посчитать пути по AI-агентам, вычтя свой адрес** — седьмое поле в combined-формате это путь запроса.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | grep -iE 'ChatGPT-User|OAI-SearchBot|GPTBot|Perplexity|Claude-User|ClaudeBot|meta-externalagent' \
     | awk '$1 != "203.0.113.9" {print $7}' | sort | uniq -c | sort -rn | head -20
   ```

   Здесь `grep` без `-o` отбирает строки целиком, так что запросы считаются сразу правильно.
### Чего эти строки не доказывают

Сравнение, ради которого всё и затевалось: 0 обращений к `llms.txt` против 56 к `robots.txt`. `robots.txt` взял каждый AI-агент из таблицы, `llms.txt` не взял ни один. Это уже, чем «файл бесполезен», — это ровно то, что подтверждает лог одной машины за 16 дней.

К `/` пришло 280 запросов, больше, чем ко всем остальным путям вместе, и прочитать это как предпочтение я не могу. Голый домен, вставленный в чат, и агент, решивший начать с корня, дают одну и ту же строку, потому что лог записывает путь и никогда не записывает причину. Делать хорошие страницы достижимыми от корня — по-прежнему здравый совет, только доказательство ему не эта таблица.

Пост со сравнением забрали 64 раза, и ещё 6 по-русски: больше, чем весь остальной блог вместе, и это всё, что знает про него nginx. Ответ 200 значит, что байты ушли, и ни одна строка файла не говорит, что хоть слово из них попало в ответ. Цитирование видно в переходах с хостов ассистентов и в самих ответах, и ни то ни другое логом не пишется.

`robots.txt` и `sitemap.xml` забрали 56 и 14 раз, и эти две строки я читаю как протокол, а не как интерес ко мне. Crawler берёт `robots.txt` в начале каждой сессии, так что большое число здесь значит, что рукопожатие работает. Про правильный sitemap никто не пишет постов, а агенты всё равно просят его раньше любой вашей прозы.

И всё это стоит на личностях, которых я не проверял, а цену окно показывает дважды. Первый раз — когда я прочитал свои же подделанные строки как тринадцать вендоров, второй — когда прочитал `Google-Extended` в строке, которой не бывает. По-хорошему нужен обратный DNS на каждый адрес клиента или сверка с диапазонами вендора.

## Что не сработало

- **Посчитать свой трафик за агентский**. Мой адрес лежит в этом логе 4 221 раз, 81 строка — под именем краулера. Я опубликовал суммы вместе со всем этим внутри, а странные строки списал на неизвестный сканер. Сканером был мой же цикл на `curl`, и выяснилось это одним запросом к `api.ipify.org`.
- **Вывод про `llms.txt` с первого захода**. Страница писала «примерно по одному обращению на агента» и строила вывод на форме этого счёта. Семнадцать строк из него — четыре секунды цикла, который я запустил 7 августа. Настоящее число обращений от AI-агентов за 16 дней — 0.
- **Прочитать живой лог и на этом остановиться**. Первый заход пришёлся на файл, начатый тем же утром, и в нём было 0 запросов к `llms.txt`. Число оказалось верным случайно, а рассуждение — нет. В архивах нашлись 45 запросов, и 44 из них были мои.
- **Опубликовать команду, которая не даёт эту таблицу**. Напечатанный здесь вариант с `grep -oE` был регистрозависимым и `bingbot` не находил вообще. С флагом регистра он считал вхождения вместо запросов, и эта строка удваивалась. Читатель, запустивший команду со страницы, получал не таблицу и не ошибку.
- **Считать календарные дни вместо дней на диске**. Сначала на этой странице между теми же датами стояло 24 дня. `logrotate` держит здесь 14 суточных архивов, и девяти из этих дней на момент подсчёта уже не было.
- **Отнести суммы к одному сайту**. Цифры собраны по всем посайтовым логам машины. 340 запросов `ChatGPT-User` из 341 принадлежат одному из этих сайтов. Разделение сделано по путям, а не по полю в логе.
- **Считать имя в логе личностью**. Каждый агент в таблицах выше — непроверенная строка `User-Agent`. Мои были откровенно поддельными, и я всё равно не скажу, какие из оставшихся строк — чей-то сканер.
- **Считать лог nginx полным счётом**. Запрос, который Cloudflare отдал из кэша, до машины не доходит. Эти цифры — нижняя граница, а не итог.
- **Забрать для сравнения цифры со стороны Cloudflare**. Запрос к API упал на правах токена, поэтому сравнения на этой странице нет. Всё, что впитал edge, в таблицы выше не попало.

## Проверить

- Напечатать свой публичный адрес и выгрепать его из лога раньше, чем читать хоть одну сумму. У меня это был самый крупный клиент машины.
- Повторить подсчёт через месяц и сравнивать форму, а не суммы: по одному окну не понять, что на вашей машине вообще нормально.
- Проверить глубину хранения в `logrotate`, прежде чем верить своему окну. У меня она оказалась больше, чем открытый первым файл.
- Запросить `/llms.txt` самому и найти эту строку в логе. Если её нет — вы читаете не тот файл.
- Посчитать коды ответа по агентам. Стена 403 значит, что кому-то отказывают, а в суммах это читается ровно как «никто не приходил».
- Считать строки, а не вхождения. Прогнать одни и те же данные через `wc -l` и через `grep -o` и сравнить суммы.
- Разрезолвить адреса главных агентов обратным DNS и сверить с диапазонами вендора.
- Снять окно, в которое вы сайт не трогаете вообще. Иначе агента, которого запускает человек, честно не прочитать, и я такого окна пока не снимал.
- Сравнить лог с аналитикой своего CDN. У Cloudflare это **AI Crawl Control**, вкладки **Crawlers** и **Metrics**. Всё, что edge закэшировал или отклонил, для nginx невидимо.
