## Что решаем

Каждый гайд советует опубликовать `llms.txt`. Ни один не показывает строку лога, где этот файл кто-то запросил.

Я прочитал свой. Одна машина, несколько маленьких сайтов, access-логи nginx по сайтам, с 19 июля по 12 августа 2026.

В окне дыра. Ничего между 20 и 28 июля ротацию не пережило, так что дальше — 16 дней записей.

Это трафик одного оператора, а не выборка по вебу. Но это замер, а у советов вокруг нет и его.

## Шаги

Сначала прочитать весь период целиком, и только потом — отдельного агента.

Мелкие строки здесь врут. Один клиент за это окно прислал с единственного IP 56 разных имён краулеров.

На него приходятся все 6 запросов ClaudeBot и все 3 от Perplexity-User. И ещё 14 из 55 у GPTBot и 12 из 34 у Claude-User.

Что запрашивали AI-агенты — ChatGPT-User, OAI-SearchBot, GPTBot, PerplexityBot, Perplexity-User, Claude-User, ClaudeBot и meta-externalagent вместе:

| Путь | Запросов |
|---|---|
| `/` | 293 |
| Пост со сравнением моделей speech-to-text | 65 |
| `/robots.txt` | 56 |
| `/ru` | 35 |
| Пост о расшифровке голосового в Telegram | 19 |
| `/sitemap.xml` | 15 |
| `/llms.txt` | 8 |
| Тот же пост со сравнением, по-русски | 7 |
| Тот же пост о расшифровке, по-русски | 3 |

`llms.txt` за весь период запросили 45 раз, всеми клиентами вместе. 26 запросов — от `curl`, то есть я сам проверял собственный файл.

Остальное — примерно по одному запросу на клиента. GPTBot, OAI-SearchBot, PerplexityBot, Perplexity-User, Claude-User, ClaudeBot, ChatGPT-User, YandexBot, Googlebot, bingbot, CCBot, Amazonbot и meta-externalagent взяли файл по разу. SiteAuditBot от Semrush взял его дважды, и все ответы были 200.

`Google-Extended` в этом списке нет, и быть не может. Своего user agent у него нет вообще. Это управляющий токен для `robots.txt`, а ходят обычные агенты Google.

Прошлая версия этой страницы его всё-таки перечисляла — потому что строка в логе так и сказала. Один клиент прислал эту строку вместе с `Bytespider`, `Applebot-Extended` и `cohere-ai`, с одного IP за две секунды.

То есть строка была настоящая, а краулер — нет. `Google-Extended` вы не выгрепаете из своего лога никогда, если только его вам не наберут руками.

1. **Писать лог по сайту, а не по машине** — строка `access_log` внутри каждого блока `server`.

   ```nginx
   server {
       server_name example.com;
       access_log /var/log/nginx/example.access.log;
   }
   ```

   Один общий лог без `$host` в `log_format` не скажет, на какой сайт пришёл запрос.
2. **Открывать ротированные архивы, а не только сегодняшний файл** — `zcat -f` читает и обычные, и gzip.

   ```bash
   zcat -f /var/log/nginx/example.access.log* | wc -l
   ```

   Глубину хранения смотреть в конфиге `logrotate`. Это и есть ваше настоящее окно.
3. **Посчитать агентов за всё окно** — по одному совпадению на запрос, без учёта регистра.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | awk 'match(tolower($0), /chatgpt-user|oai-searchbot|gptbot|perplexitybot|perplexity-user|claude-user|claudebot|meta-externalagent|googlebot|bingbot|yandexbot|applebot|amazonbot/) {
         print substr(tolower($0), RSTART, RLENGTH)
       }' \
     | sort | uniq -c | sort -rn
   ```

   Очевидный вариант через `grep -oE` неверен дважды, и эта страница его публиковала. Bing зовёт себя строчными `bingbot`, так что регистрозависимый шаблон не находит его вовсе.
   Чините регистр — вылезает вторая ошибка: `grep -o` печатает вхождения, а не строки. Запрос от bingbot называет себя дважды: в токене и в URL `+http://…/bingbot.htm`.
   В этом окне это 336 вхождений против 155 запросов. `awk` берёт первое совпадение в строке: одна строка — один запрос.
4. **Посчитать пути, только по AI-агентам** — седьмое поле в combined-формате это путь запроса.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | grep -iE 'ChatGPT-User|OAI-SearchBot|GPTBot|Perplexity|Claude-User|ClaudeBot|meta-externalagent' \
     | awk '{print $7}' | sort | uniq -c | sort -rn | head -20
   ```

   Здесь `grep` без `-o` отбирает строки целиком, так что запросы считаются сразу правильно.
5. **Вычесть свои проверки** — каждый `curl`, которым вы дёргали файл, лежит в том же логе.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | awk '$7 == "/llms.txt"' | grep -vic curl
   ```

   У меня 45 запросов превратились в 19, как только `curl` вышел из подсчёта.
6. **Сравнить `llms.txt` с `robots.txt`** — 8 запросов против 56, в семь раз меньше.
   Каждый агент берёт файл примерно раз за окно. Это оглавление, в которое заглядывают, а не маршрут, по которому ходят.
   Утверждение слабее, чем «файл бесполезен», и именно его подтверждает лог.
7. **Ждать, что визит на себя примет главная** — 293 запроса к `/`, больше, чем ко всем остальным путям вместе.
   На корень агент приземляется и там решает, что забрать. То, что вы хотите видеть в цитате, должно быть достижимо оттуда.
8. **Найти страницу, которая обошла все остальные** — сравнение моделей speech-to-text, 65 запросов и ещё 7 по-русски.
   Это больше, чем весь остальной блог вместе. Таблица сравнения даёт агенту строку, которую можно процитировать.
9. **Потратить вечер на `robots.txt` и `sitemap.xml`** — 56 и 15 запросов, настоящие точки входа.
   Про правильный sitemap никто не пишет постов. Агенты просят его раньше, чем любую вашу прозу.
10. **Проверять личность по сети, прежде чем всему этому верить** — я не проверял, и это окно показывает цену.
    Один IP прислал 56 разных имён краулеров, включая `Google-Extended`, которому и присылать-то нечего.
    По-хорошему нужен обратный DNS на каждый IP клиента или сверка с диапазонами вендора.

## Что не сработало

- **Прочитать живой лог и на этом остановиться**. Первый заход пришёлся на файл, начатый тем же утром, и в нём было 0 запросов к `llms.txt`. Из такого чтения выходил вывод сильнее и при этом неверный. В ротированных архивах нашлись 45 запросов, и ответ вместе с ними поменялся.
- **Опубликовать команду, которая не даёт эту таблицу**. Напечатанный здесь вариант с `grep -oE` был регистрозависимым и `bingbot` не находил вообще. С флагом регистра он считал вхождения вместо запросов, и эта строка удваивалась. Читатель, запустивший команду со страницы, получал не таблицу и не ошибку.
- **Считать календарные дни вместо дней на диске**. Сначала на этой странице между теми же датами стояло 24 дня. `logrotate` держит здесь 14 суточных архивов, и девяти из этих дней на момент подсчёта уже не было.
- **Отнести суммы к одному сайту**. Цифры собраны по всем посайтовым логам машины, а не по одному сайту. Пути достаточно характерные, чтобы уверенно сказать, чей это сайт, — но это вывод, а не замер.
- **Считать имя в логе личностью**. Каждый агент в таблицах выше — непроверенная строка `User-Agent`. Один клиент прислал сюда 56 таких строк с одного IP, включая токен, у которого user agent нет вовсе. Часть строк в таблице — чей-то сканер, и какая именно, я сказать не могу.
- **Считать лог nginx полным счётом**. Запрос, который Cloudflare отдал из кэша, до машины не доходит. Эти цифры — нижняя граница, а не итог.
- **Забрать для сравнения цифры со стороны Cloudflare**. Запрос к API упал на правах токена, поэтому сравнения на этой странице нет. Всё, что впитал edge, в таблицы выше не попало.

## Проверить

- Повторить подсчёт через месяц и сравнивать форму, а не суммы. Одно окно — это снимок.
- Проверить глубину хранения в `logrotate`, прежде чем верить своему окну. У меня она оказалась больше, чем открытый первым файл.
- Запросить `/llms.txt` самому и найти эту строку в логе. Если её нет — вы читаете не тот файл.
- Посчитать коды ответа по агентам. Стена 403 — это блокировка, а не отсутствие интереса.
- Считать строки, а не вхождения. Прогнать одни и те же данные через `wc -l` и через `grep -o` и сравнить суммы.
- Разрезолвить IP главных агентов обратным DNS и сверить с диапазонами вендора.
- Сравнить лог с аналитикой своего CDN. Всё, что закэшировал edge, для nginx невидимо.
