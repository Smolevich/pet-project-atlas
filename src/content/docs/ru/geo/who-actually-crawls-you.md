## Что решаем

Каждый гайд советует опубликовать `llms.txt`. Ни один не показывает строку лога, где этот файл кто-то запросил.

Я прочитал свой. Одна машина, несколько маленьких сайтов, access-логи nginx с 19 июля по 12 августа 2026 — около 24 дней.

Это трафик одного оператора, а не выборка по вебу. Но это замер, а у советов вокруг нет и его.

## Шаги

Сначала прочитать весь период целиком, и только потом — отдельного агента.

Что запрашивали AI-агенты — ChatGPT-User, OAI-SearchBot, GPTBot, PerplexityBot, Perplexity-User, Claude-User, ClaudeBot и meta-externalagent вместе:

| Путь | Запросов |
|---|---|
| `/` | 409 |
| Пост со сравнением моделей speech-to-text | 108 |
| `/robots.txt` | 90 |
| `/ru` | 36 |
| `/sitemap.xml` | 26 |
| Пост о расшифровке голосового в Telegram | 19 |
| `/llms.txt` | 8 |
| Тот же пост со сравнением, по-русски | 7 |
| Тот же пост о расшифровке, по-русски | 4 |

`llms.txt` за весь период запросили 38 раз, всеми клиентами вместе. 22 запроса — от `curl`, то есть я сам проверял собственный файл.

Остальное — примерно по одному запросу на агента за 24 дня: GPTBot, OAI-SearchBot, PerplexityBot, Perplexity-User, YandexBot, Google-Extended и meta-externalagent. SiteAuditBot от Semrush взял файл дважды, ещё пара открытий пришла из браузера. Все ответы были 200, так что блокировки здесь нет.

1. **Писать лог по сайту, а не по машине** — строка `access_log` внутри каждого блока `server`.

   ```nginx
   server {
       server_name example.com;
       access_log /var/log/nginx/example.access.log;
   }
   ```

   Один общий лог без `$host` в `log_format` не скажет, на какой сайт пришёл запрос.
2. **Открывать ротированные архивы, а не только сегодняшний файл** — `zcat -f` читает и обычные, и gzip.

   ```bash
   zcat -f /var/log/nginx/example.access.log* | wc -l
   ```

   Глубину хранения смотреть в конфиге `logrotate`. Это и есть ваше настоящее окно.
3. **Посчитать агентов за всё окно** — один grep, потом sort.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | grep -oE 'ChatGPT-User|OAI-SearchBot|GPTBot|PerplexityBot|Perplexity-User|Claude-User|ClaudeBot|meta-externalagent|Googlebot|Bingbot|YandexBot|Applebot|Amazonbot' \
     | sort | uniq -c | sort -rn
   ```
4. **Посчитать пути, только по AI-агентам** — седьмое поле в combined-формате это путь запроса.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | grep -E 'ChatGPT-User|OAI-SearchBot|GPTBot|Perplexity|Claude-User|ClaudeBot|meta-externalagent' \
     | awk '{print $7}' | sort | uniq -c | sort -rn | head -20
   ```
5. **Вычесть свои проверки** — каждый `curl`, которым вы дёргали файл, лежит в том же логе.

   ```bash
   zcat -f /var/log/nginx/example.access.log* \
     | awk '$7 == "/llms.txt"' | grep -vc curl
   ```

   У меня 38 запросов превратились в 16, как только `curl` вышел из подсчёта.
6. **Сравнить `llms.txt` с `robots.txt`** — 8 запросов против 90, в одиннадцать раз меньше.
   Каждый агент берёт файл примерно раз в месяц. Это оглавление, в которое заглядывают, а не маршрут, по которому ходят.
   Утверждение слабее, чем «файл бесполезен», и именно его подтверждает лог.
7. **Ждать, что визит на себя примет главная** — 409 запросов к `/`, больше, чем ко всем остальным путям вместе.
   На корень агент приземляется и там решает, что забрать. То, что вы хотите видеть в цитате, должно быть достижимо оттуда.
8. **Найти страницу, которая обошла все остальные** — сравнение моделей speech-to-text, 108 запросов и ещё 7 по-русски.
   Это больше, чем весь остальной блог вместе. Таблица сравнения даёт агенту строку, которую можно процитировать.
9. **Потратить вечер на `robots.txt` и `sitemap.xml`** — 90 и 26 запросов, настоящие точки входа.
   Про правильный sitemap никто не пишет постов. Агенты просят его раньше, чем любую вашу прозу.
10. **Проверять личность по сети, прежде чем всему этому верить** — я не проверял, и это дыра.
    Строка `User-Agent` — это заявление, и отправить её может кто угодно. По-хорошему нужен обратный DNS на каждый IP клиента или сверка с диапазонами вендора.

## Что не сработало

- **Прочитать живой лог и на этом остановиться**. Первый заход пришёлся на файл, начатый тем же утром, и в нём было 0 запросов к `llms.txt`. Из такого чтения выходил вывод сильнее и при этом неверный. В ротированных архивах нашлись 38 запросов, и ответ вместе с ними поменялся.
- **Отнести суммы к одному сайту**. 24 дня взяты из общего лога nginx на машине, а он не пишет `$host`. Логи по сайтам появились позже. Пути достаточно характерные, чтобы уверенно сказать, чей это сайт, — но это вывод, а не замер.
- **Считать имя в логе личностью**. Каждый агент в таблицах выше — непроверенная строка `User-Agent`. Соседняя страница атласа велит сверяться с опубликованными диапазонами IP или обратным DNS. Этой сверки я не делал.
- **Считать лог nginx полным счётом**. Запрос, который Cloudflare отдал из кэша, до машины не доходит. Эти цифры — нижняя граница, а не итог.
- **Забрать для сравнения цифры со стороны Cloudflare**. Запрос к API упал на правах токена, поэтому сравнения на этой странице нет. Всё, что впитал edge, в таблицы выше не попало.

## Проверить

- Повторить подсчёт через месяц и сравнивать форму, а не суммы. Одно окно — это снимок.
- Проверить глубину хранения в `logrotate`, прежде чем верить своему окну. У меня она оказалась больше, чем открытый первым файл.
- Запросить `/llms.txt` самому и найти эту строку в логе. Если её нет — вы читаете не тот файл.
- Посчитать коды ответа по агентам. Стена 403 — это блокировка, а не отсутствие интереса.
- Разрезолвить IP главных агентов обратным DNS и сверить с диапазонами вендора.
- Сравнить лог с аналитикой своего CDN. Всё, что закэшировал edge, для nginx невидимо.
