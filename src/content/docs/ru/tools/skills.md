## Что решаем

Своего аудита я в атлас не кладу и не собираюсь. Хорошие инструменты уже написаны, и моя версия любого из них была бы худшей копией, которую никто не станет поддерживать, включая меня самого.

Чего мне не хватало, так это карты: какой инструмент отвечает на какой вопрос, в каком порядке и что можно пропустить, когда симптом уже говорит, куда смотреть.

Эта карта — команды `/atlas:` в конце таблицы, и аудита среди них нет. `/atlas:start` вызывает чужие аудиты и раскладывает находки по маршруту. Остальные заняты тем, на что аудита не существует: план текстов, недельный срез цифр, вычитка черновика.

Каждая сторонняя строка ниже — пакет, который стоит у меня на машине. Исключение одно — платный сервис, и лицензию я смотрел в исходном репозитории, а для сервиса — в том, что покупается за деньги.

### Откуда эти скиллы берутся и где лежит их лицензия

CLI скиллов принимает владельца и имя репозитория. Установка сторонних — две строки:

```bash
npx skills add -g coreyhaines31/marketingskills
npx skills add -g zubair-trabzada/geo-seo-claude
```

Флаг `-g` здесь обязателен. Без него установщик кладёт скилл в текущий проект, и в соседней папке его уже нет, а сайты вы проверяете из разных мест. Сам пакет ложится в `~/.agents/skills/`, а в `~/.claude/skills/` уходит симлинк, поэтому установленное ищут в обоих каталогах сразу.

Лицензия вместе с ними не приезжает. В установленном `SKILL.md` нет ни строки о лицензии, ни автора, ни имени репозитория, а происхождение выживает в одном месте — в lock-файле, который написал установщик:

```bash
cat ~/.agents/.skill-lock.json
```

Оттуда берём имя репозитория и идём читать лицензию в сам репозиторий.

### С чего начинать, когда в индексе пусто

С `seo-audit`. Он проходит забор, блокировку и canonical за один заход — это быстрее, чем проверять семь вещей руками, и заметно громче, когда одна из них сломана.

На стороне GEO порядок важнее выбора. `geo-crawlers` раньше `geo-citability`, всегда. Доступ решает, прочитают ли текст вообще.

Один раз я запустил их наоборот и получил бодрый отчёт о цитируемости страницы, которую неделями не забирал ни один агент.

### Зачем нужен сводный балл, если он двигается от чего угодно

`geo-audit` — для замера, точечный скилл — для починки: сводное число двигается от любого изменения, поэтому само по себе оно говорит мало.

Перезапустите тот же аудит после работы и читайте разницу. Вот на разницу я и смотрю.

### Когда браузер — единственный способ попасть в панель

Playwright MCP окупается там, где API просто нет. Панель за логином, консоль без кнопки экспорта.

Водить надо свой профиль, тогда авторизованные сессии уже на месте, а чистый профиль показывает форму входа и больше ничего.

### Что покрывает gws, а что нет

```bash
gws --help
```

Список печатает ваша же установленная сборка, и ответ — этот список, а не то, что написано в гайде. Он покрывает Workspace.

Search Console и Analytics в нём нет, и в блоке ниже я как раз выясняю это долгим путём.

### Как подключаются четыре команды /atlas:

Две строки в Claude Code — добавить этот репозиторий как marketplace, потом поставить плагин:

```text
/plugin marketplace add Smolevich/pet-project-atlas
/plugin install atlas
```

Сам аудит остаётся за сторонними скиллами выше, и это осознанно. `/atlas:start` не проверяет ничего сам, он решает, какой чужой скилл запустить и в каком порядке читать то, что они вернули.

В Search Console `/atlas:report` ходит одним из двух путей и говорит, каким именно, до первого запроса. Дешёвый — браузер, в котором вы уже залогинены: Playwright MCP открывает отчёт Performance в вашем же профиле, без проекта в облаке и без токена. Второй — REST API, и он стоит проекта с включённым API, токена со скоупом `webmasters.readonly` и quota project, без которого Search Console отвечает 403.

Браузер — когда отчёт вы снимаете руками по понедельникам. API — когда он должен сниматься сам.

Остальные три работают сами, но аудитом не заняты: `/atlas:content-plan` собирает кластеры, `/atlas:report` ходит в API Search Console, `/atlas:voice` вычитывает черновик по `STYLE.md`. Поддерживать это дешевле, чем второй движок аудита.

## Что не сработало

- **Тянуть числа Search Console через `gws`**. В справке есть форма `<api>:<version>` для неперечисленных API. Я попробовал `searchconsole:v1` и `analyticsdata:v1beta`, оба вернулись неизвестными сервисами. Эти числа берутся из их собственных API или руками из консоли.
- **Искать лицензию внутри установленного скилла**. Колонку «Лицензия» в таблице выше надо было чем-то заполнить, и я пошёл смотреть в сами папки. Там `SKILL.md` и скрипты — ни лицензии, ни автора, ни имени репозитория. Условия живут в исходном репозитории, а его имя выживает только в lock-файле.
- **Считать балл аудита работой**. Сводное число двигается от чего угодно. Поведение мне меняла одна строка отчёта. Агент, получивший 403. Кусок текста, который никто не мог процитировать.
- **Гонять проверки цитируемости, пока crawler заблокирован**. Отчёт бодро оценивал мою прозу. Страницу неделями не забирал ни один агент. Я ставил оценку документу, который никто не скачивал.
- **Водить чистый профиль браузера по панелям за логином**. Каждый запуск начинался с экрана входа. До панели доезжает только профиль с живой сессией.
- **Верить, что этот список стабилен**. У сторонних скиллов между обновлениями меняются владельцы, лицензии и поведение. Проверяйте репозиторий в день установки и перед тем, как копировать что-то к себе.

## Проверить

- `cat ~/.agents/.skill-lock.json` и прочитать `sourceUrl` каждого установленного скилла. Это и есть репозиторий, чья лицензия на вас действует.
- Открыть этот репозиторий и прочитать в нём файл `LICENSE`. Файла нет — условия неизвестны, а неизвестны значит не распространять.
- Запустить `gws --help` и найти свой сервис в напечатанном списке. Отсутствующий сервис отсутствует, что бы ни писали в гайде.
- Запустить `seo-audit` по странице, которую вы уже починили. Если отчёт всё ещё её ругает, починка не доехала до прода.
- Запустить `geo-crawlers` из сети, которая не ваша. Карта доступа, снятая изнутри вашей сети, прячет правила на edge.
